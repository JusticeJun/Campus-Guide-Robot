# 웹 기반 캠퍼스 임무

기존 navigation 위에 `campus_mission`을 별도 실행한다. 웹은 장소 선택·위치와 경로 표시·카메라 미리보기·임무 취소·관찰 기록을 제공한다. React 화면은 빌드되어 있어 실행 시 Node.js가 필요 없다.

```text
브라우저 → FastAPI → 임무 해석 API → Mission Manager
                                    ├─ Nav2 Action → 기존 주행 시스템
                                    └─ 도착 후 새 사진 → 이미지 분석 API → 웹 보고
```

ROS 연결은 별도 프로세스에서 처리한다. 웹/모델 API 대기 때문에 ROS executor를 막지 않는다. 웹은 속도·PWM을 직접 제어하지 않는다. 서비스 모드에서는 사용자가 준비 버튼을 누르면 기존 주행 런치를 시작하고, 준비 확인 후 MAVROS로 GUIDED·시동을 요청한다. 새로운 주행 중 HOLD 조건을 추가하지 않았다.

## 전원 연결 후 웹으로 사용

이 Jetson에는 사용자 systemd 웹 서비스와 로그인 없이 시작하는 linger를 설치했다.
부팅 시 **웹과 외부 터널만 자동으로 시작**한다. navigation은 부팅이나 브라우저 재접속으로 자동 실행/시동되지 않는다.
SSD 마운트가 완료된 뒤 웹이 시작되며, 웹 장애 시 재시작하되 이전 임무나 시동 절차를 자동 재개하지 않는다.

1. Jetson·로버 전원을 연결하고 같은 네트워크에 접속한다.
2. 전달받은 **HTTPS 제어 링크**를 노트북·휴대폰 브라우저에서 연다. Jetson과 다른 네트워크에서도 접속할 수 있다.
3. 로그인·암호 입력 없이 대시보드가 열리면 **주행 준비·시동**을 누른다.
4. 센서/지도 실행 → 위치추정 준비 → 정지 확인 → GUIDED 전환 → 시동 상태 확인 순서로 진행된다.
5. 지도에서 차량 위치·방향을 확인하고 목적지를 선택한다. 목표를 주기 전에는 이동 명령을 보내지 않는다.
6. 종료할 때 **시동 해제**를 누른다. 현재 Nav2 Goal(웹 재시작 전 목표나 RViz 목표 포함) 취소·HOLD·정지 확인 후 시동을 해제하며 센서와 지도는 유지된다.

현재 외부·로컬 제어 링크 확인:

```bash
bash ~/ros2_ws/src/apps/campus_mission/deploy/show-access.sh
```

링크에는 `#access=...` 형태의 제어 키가 포함된다. 브라우저가 이를 저장한 뒤 주소창에서 제거하므로 로그인 화면은 없다. 제어 키 없는 API 요청은 차단한다. **링크를 받은 사람은 차량 시동·목적지 지정과 사진 열람이 가능하므로**, 함께 사용할 사람에게만 전달한다. API 키는 이 링크에 포함하지 않는다.

대시보드 오른쪽 위 **제어 링크 복사**를 누르면 현재 외부 주소가 있으면 그 주소를 복사한다. 새 브라우저에서는 전체 링크를 열어야 하며 주소창에 남은 키 없는 URL만 전달하면 제어할 수 없다. 기존 접속 권한을 회수하려면 `mission.env`의 `CAMPUS_WEB_TOKEN`을 새 무작위 값으로 바꾸고 웹을 재시작한 뒤 새 링크를 배포한다.

외부 연결은 Cloudflare Quick Tunnel을 사용한다. Jetson에서 Cloudflare로 연결하므로 공유기 포트 포워딩을 설정하지 않는다. **Jetson 인터넷 연결은 필요하다.** 웹과 터널 모두 부팅 자동 실행으로 등록한다. 터널 재생성/재부팅 시 임시 호스트명이 바뀌므로 최신 링크를 다시 공유해야 한다. 고정 도메인 운영은 추후 named tunnel로 전환한다.

기본 호스트명만 연 경우에는 제어 링크로 접속하라는 안내가 표시된다. 같은 네트워크에서는 `show-access.sh`가 출력하는 로컬 제어 링크도 사용할 수 있다. 로컬 HTTP 링크는 암호화되지 않으므로 외부에는 HTTPS 링크를 전달한다.
`Same-network IP link`는 IP를 직접 사용하므로 외부 도메인이나 `jetson.local`의 DNS 조회 없이 접속할 수 있다. 같은 네트워크에서도 단말 간 접근을 차단한 망에서는 사용할 수 없다. 외부 링크의 DNS 오류는 서버 HTTP 오류와 구분하고, 모바일 데이터 등 다른 접속망에서 같은 최신 링크를 비교한다.

준비 버튼은 **시동까지 요청하는 버튼**이다. 차량 주변을 확인하고 누른다. 시작 단계에서 기존 준비 상태와 map 일치, 정지, FCU 응답을 확인하며 강제 arming이나 PreArm 우회는 하지 않는다. 주행 중에는 기존 주행/정지 정책을 사용하고 새로운 HOLD 감시 루프는 추가하지 않았다. 준비가 실패하면 오류를 표시하고 런치를 유지해 다시 준비할 수 있다.

준비 완료 여부는 현재 FCU 연결·시동·GUIDED와 주행 준비 상태로 표시한다. 완료 상태에서는
**준비 완료 · 시동 켜짐** 버튼을 비활성화하고, 상태가 해제되면 다시 준비할 수 있다.
중복 준비 요청은 서버에서도 최신 상태를 확인해 불필요한 모드·시동 요청 없이 완료로 반환한다.
QGC 등에서 웹 명령과 다른 시동·모드 변경이 관측되면 진행 중인 웹 준비와 자동 재시도를 중단한다.
그 뒤 준비 취소가 늦게 도착해도 수동으로 선택한 상태를 되돌리지 않는다. 다시 웹 준비를 누를 때만 현재 상태에서 새 절차를 시작한다.
FCU 상태 메시지만으로 명령 발신자를 구분할 수 없으므로 FCU 자체 상태 변경·연결 단절에도 같은 중단 원칙을 적용한다.
정지 확인은 최근 1.2초의 속도 분포와 위치·방향 변화를 함께 확인해 단발성 라이다 속도 잡음을
허용하며, 지속 이동·큰 위치 변화·수신 중단은 정지로 인정하지 않는다. 주행 중 제어 가드는 바꾸지 않는다.

### 준비 진행·취소·재시도

준비 카드에서 경과 시간과 Pixhawk 연결, 카메라 영상, 지도 로딩, 현재 위치 TF,
위치·속도 전송, 주행 준비 판정, GUIDED, 실제 시동 응답을 확인한다.
각 표시는 실제 수신 상태이며, 지도 로딩·TF 수신만으로 지도 정합 성공을 단정하지 않는다.
오류가 고정된 ExternalNav 상태는 무한 대기 대신 오류 이유를 표시한다.

- **준비 취소:** 진행 중 자동 준비·시동 요청을 취소한다. 센서·RTAB-Map·Nav2는 유지한다.
  해당 준비 요청에서 이미 시동 명령을 보냈다면 완료 여부를 확인하고 그 시동을 해제한다.
  준비 전부터 켜져 있던 시동은 건드리지 않는다. 이는 이동 중 **임무 일시정지**와 별도 기능이다.
- **다시 준비 · 시동:** 취소 확인 또는 실패 뒤 현재 실행 중인 navigation을 재사용한다.
  취소 확인 중에는 겹치는 새 시동 요청을 보내지 않는다. 센서 오류 자체를 무시하거나 초기화하지 않는다.
- 카메라 웹 영상은 기본적으로 `/camera/camera/color/image_raw/compressed`를 사용한다.
  원본 영상만 제공하는 카메라는 `--image-transport raw`로 선택할 수 있다.

### 주행 실패 후 복구

준비 중 프로세스 조회·상태 수신·복구 서비스의 일시 오류는 해당 단계만 최대 3회 시도한다.
GUIDED/시동 확인 실패는 이전 시동 요청의 취소 완료를 확인한 뒤 새 요청으로 상태 확인부터
최대 3회 시도한다. 취소 미확인 또는 반복되는 위치 불연속은 자동 재시도를 중단하고 원인을 표시한다.
사용자가 누른 준비 취소는 자동 재시도하지 않는다. 전체 센서·지도 런치를 재시작하지 않는다.

준비 버튼은 서버의 최신 상태를 기준으로 일반 준비와 실패 복구를 자동 선택한다.
위치 추정/ExternalNav 오류로 Goal이 취소되면 같은 버튼이 **오류 복구 · 다시 준비**로 표시된다.
브라우저가 이전 화면을 표시해도 일반 준비 요청에서 필요한 복구 절차로 전환한다.
전송 노드가 시동 해제 확인을 기다리는 경우에도 이미 켜진 시동 상태를 먼저 정리한다.
HOLD 응답 뒤 시동 해제에는 오도메트리의 정지 판정을 요구하지 않아, 추정 오류로 시동 해제까지 막히지 않는다.
재시동과 위치 입력 재초기화에는 기존 정지·입력 검사를 유지한다.
이 절차는 종료된 Goal을 확인하고 시동을 해제한 뒤, 현재 위치 TF·지도 일치·정지와
연속된 정상 오도메트리를 확인한다. 좌표 불연속 오류에는 명시적인
`/external_navigation/reinitialize` 요청으로 MAVLink odometry reset counter를 새로 기록한다.
RTAB-Map, local EKF, 센서, 지도 TF 자체는 초기화하지 않는다.
FCU가 다시 준비되면 tracking stop을 해제하고 GUIDED·시동을 확인한다.
**완료 후 원하는 목적지를 다시 선택한다. 이전 Goal은 자동 재개하지 않는다.**

이 동작은 센서 오류를 무시하는 기능이 아니다. 재초기화 뒤 오류가 다시 발생하면
연속 초기화를 중단하고 원인을 표시한다. 주행 중 시동/좌표 재초기화는 허용하지 않는다.
일반 임무 일시정지·취소에는 시동 해제나 이 복구 절차를 사용하지 않는다.

### 이동 중 일시정지·재개·취소

단순 목적지 버튼과 자연어 임무 모두 **임무 진행 상황**의 동일한 제어 버튼을 사용한다.

- **일시정지:** `/navigation/set_motion_paused`로 Guard 출력을 즉시 0으로 제한한다. `OperatorPause` BT가 하위 경로 계산·추종 작업을 중단하지만 상위 `NavigateToPose` Goal은 RUNNING으로 유지한다. 추종 작업의 진행 시간초과가 정지 중 누적되지 않는다. 오도메트리로 정지를 확인하면 재개 버튼을 표시한다.
- **임무 재개:** 같은 Nav2 Goal과 목적지로 하위 작업을 다시 진행한다. 현재 위치·장애물에 따라 경로는 다시 계산될 수 있다.
- **임무 취소:** 출력을 0으로 제한하고 상위 Nav2 Goal도 취소한다. 취소 완료 후 새 목적지나 자연어 임무를 받을 수 있다.

위 버튼은 FCU 모드 변경·시동 해제·navigation/RTAB-Map 종료를 요청하지 않는다. 정상 상태에서는 armed·GUIDED와 위치추정이 유지되고 런치 재시작이 필요 없다. 센서 추적 자체가 실패하면 위치 정확도까지 보장되는 것은 아니며 기존 FCU/주행 오류 처리는 유지한다. 통신 두절 시 원격 버튼 전달을 보장할 수 없으므로 물리 비상정지와 구분한다. 촬영·분석 단계에서는 이동 일시정지 대신 임무 취소를 사용한다.

처음 서비스로 전환할 때 기존 tmux/터미널 센서·매핑 런치를 정상 종료한다. 이미 완성된 navigation이 실행 중이면 중복 실행하지 않고 현재 지도와 상태를 확인해 재사용한다. 센서만 따로 실행한 상태에서는 첫 전환 때 이를 종료하도록 안내한다. RViz와 웹에서 동시에 Goal을 주지 않는다.

## 설정·설치와 관리

장비별 설정과 키는 `~/.config/campus-rover/mission.env`에 둔다. 설치 스크립트는 파일이 없을 때만 예제를 복사하고 무작위 제어 링크 키를 생성한다. 기존 설정은 덮어쓰지 않는다.

- `CAMPUS_MAP_DIR`: 자동 주행에 사용할 지도 폴더. 현재 map1.
- `CAMPUS_NAV_ODOMETRY`: 기본 `auto`. 카메라 전용 map1에서는 카메라 추정을 사용한다. 현재 map1에서 ICP 속도 융합으로 가짜 움직임·위치 불연속이 재현돼 실차 융합 사용을 보류했다. 라이다 포함 지도의 `auto`는 융합을 선택하므로 해당 구성은 별도 검증이 필요하다.
- `CAMPUS_LIDAR_OBSTACLES`: 기본 `true`. 오도메트리 선택과 별개로 라이다 장애물 감속·정지·우회를 유지한다. 서비스는 카메라·라이다·MAVROS를 모두 실행한다. 카메라 추정 모드에서는 카메라가 추적을 잃으면 라이다가 위치 추정을 대신하지 않는다.
- `CAMPUS_RVIZ`: 기본 false. 웹에서 위치·경로를 보므로 VNC/RViz 실행이 필요 없다.
- `CAMPUS_WEB_TOKEN`: 제어 링크용 키. 로그인 암호 입력에 사용하지 않는다. API 키와 다르다.
- `OPENAI_API_KEY`: 자연어 해석·현장 분석용 키. 비워두어도 장소 버튼으로 이동·촬영할 수 있다.
- `CAMPUS_LLM_MODEL`, `CAMPUS_VLM_MODEL`: 해당 API 계정에서 사용 가능한 모델 ID. 실제 API 호출은 키 등록 후 확인한다.

값에 공백/셸 특수문자가 있으면 작은따옴표로 감싼다. 설정 파일은 셸에서 읽는 신뢰된 로컬 파일이며 웹으로 수정하지 않는다. 키를 Git이나 웹 입력창에 넣지 않는다.

```bash
nano ~/.config/campus-rover/mission.env
systemctl --user restart campus-web  # 설정 변경 반영; 실행 중 임무가 없을 때
```

새 장비에 설치할 때(ROS Humble 빌드 완료, `~/ros2_ws` 준비):

```bash
python3 -m pip install --user -e ~/ros2_ws/src/apps/campus_mission
bash ~/ros2_ws/src/apps/campus_mission/deploy/install-user-services.sh
systemctl --user start campus-web
bash ~/ros2_ws/src/apps/campus_mission/deploy/install-tunnel.sh
systemctl --user start campus-tunnel
```

서비스는 `~/ros2_ws` 경로를 사용한다. 현재 장비는 사용자 홈 전체가 SSD에 있으므로 별도의 `~/ssd` 경로가 필요 없다. 다른 경로로 배포한다면 서비스 파일과 실행 스크립트 경로를 조정한다. 다른 장비에서 `loginctl enable-linger`가 거절되면 관리자에게 해당 사용자 linger 활성화를 요청한다.

```bash
systemctl --user status campus-web campus-tunnel campus-navigation
journalctl --user -u campus-web -n 50 --no-pager
journalctl --user -u campus-tunnel -n 30 --no-pager
journalctl --user -u campus-navigation -f
```

전체 종료/지도 변경 시 먼저 웹에서 시동을 해제하고:

```bash
systemctl --user stop campus-navigation
systemctl --user restart campus-web
```

navigation 서비스는 자동 재시작하지 않는다. 웹이 종료되어도 navigation은 유지된다. 강제 프로세스 종료 때 Nav2 취소 전달을 보장하지 않으므로 상태를 확인한다. 외부 접속을 닫고 자동 연결도 해제하려면 `systemctl --user disable --now campus-tunnel`을 사용한다. 웹 자동 실행도 해제하려면 `systemctl --user disable --now campus-web`을 추가한다.

## 개발용 수동 실행

자동 웹 서비스와 같은 포트에서 중복 실행하지 않는다. 센서 없이 화면/좌표만 확인할 때:

```bash
bash ~/ros2_ws/src/tools/campus_web.sh --mode preview \
  --map-dir "$HOME/ros2_ws/maps/test_map/map1" --port 8081 \
  --data-dir "$HOME/ros2_ws/mission_data/preview"
```

VNC 또는 SSH 포트 전달로 `http://127.0.0.1:8081/#access=<제어 링크 키>`에 접속한다. 키는 `show-access.sh`가 출력하는 링크의 `#access=` 뒤 값이며, 미리보기는 실제 차량과 연결하지 않는다. 별도 데이터 폴더로 자동 웹 서비스와 임무 저장소 잠금이 충돌하지 않게 한다.
기존 수동 navigation에 웹 임무만 연결하려면 같은 ROS 환경에서 `--mode live --map-dir "$MAP_DIR"`로 실행한다. 이 경우 `--service-controls`를 주지 않으면 시동/서비스 시작 버튼은 표시하지 않는다.

## 장소와 지도 교체

장소는 **`$MAP_DIR/places.yaml`**에 저장한다. RTAB-Map DB 자체는 웹에서 읽거나 수정하지 않는다. 2D 이미지와 해상도·원점 등의 fingerprint로 장소 파일을 지도에 연결하고, live 실행 시 `/map` 내용도 대조한다.

현재 map1에 제공된 표시를 옮긴 초기값:

| 번호 | ID | 표시 이름 | x (m) | y (m) | yaw (rad) |
|---|---|---|---:|---:|---:|
| 1 | nuri | 누리관 | 1.829 | -0.494 | -2.594 |
| 2 | woongbi | 웅비관 | 28.344 | -30.968 | -2.200 |
| 3 | plaza | 광장중앙 | 57.279 | -7.805 | 0.015 |

이미지 표시에서 추정한 좌표이며 실측한 관찰 자세가 아니다. 원본은 `apps/campus_mission/config/map1.places.yaml`에 있다. 같은 지도에서 장소 파일이 없을 때만 초기값을 적용한다. 각 목적지 중심이 빈 공간인 것은 확인했지만 차량 전체 공간과 실제 관찰 방향은 현장에서 확인해야 한다.

웹의 **좌표·관찰 방향 수정**에서 지도 위 위치를 누르고 바라볼 방향으로 드래그하거나 x/y/방향을 입력한다. 실제 로버를 원하는 자세에 놓고 **현재 로버 자세 가져오기**로 저장할 수도 있다. YAML yaw는 rad, 화면은 도 단위다. 기존 임무 중에는 좌표를 바꿀 수 없다.

새 카메라+라이다 지도를 쓸 때:

1. 새 지도 폴더에 `rtabmap.yaml`과 이미지 등 기존 주행 파일을 준비한다.
2. 서비스 모드에서는 시동 해제·navigation 종료 후 `mission.env`의 `CAMPUS_MAP_DIR`을 바꾸고 웹을 재시작한다. 수동 실행에서는 navigation과 웹 모두 같은 새 `MAP_DIR`로 실행한다.
3. 새 지도에는 장소 목록이 비어 있다. 웹의 **장소 등록**으로 다시 지정한다.

다른 지도에 map1 좌표를 자동으로 적용하지 않는다. 이어 매핑/지도 재저장으로 이미지가 바뀐 경우에도 기존 `places.yaml`을 별도 보관하고 좌표를 확인·재등록한다. 단순 폴더 이동은 지도 내용이 같으면 가능하다.

카페·주차장·흡연장은 `category`를 각각 `cafe`, `parking`, `smoking_area`로 등록하면 가까운 후보 조회와 현장 관찰에 사용할 수 있다. 카메라에서 실제 대상이 보이는 위치·방향을 지정한다. 현재 초기 세 장소 외 다른 시설 좌표는 등록되어 있지 않다.

## 임무 동작

| 요청 | 실행 |
|---|---|
| 누리관으로 가 줘 | x/y는 고정, 도착 yaw 후보 최대 5개를 Nav2로 계산해 선택 |
| 웅비관 입구로 가서 사진 찍어 줘 | 저장된 x/y/yaw로 이동 → 정지 → 새로운 사진 2장 저장 |
| 광장중앙 상태를 보여 줘 | 관찰 자세 이동 → 촬영 → 보이는 근거와 판단 한계를 보고 |
| 가까운 주차장에 자리 있나 확인해 줘 | 등록된 주차장 중 가까운 최대 3곳의 접근 경로 비교 → 이동·관찰 |
| 가까운 흡연장이 어디야 | 등록된 후보를 알려줌. 실제 이동은 이동 요청을 받아 실행 |

단순 이동의 경로 비교는 길이·후진·기어 전환 비용을 사용한다. 모든 가능한 yaw를 최적화하는 전역 최단경로 보장은 아니다. 관찰은 일반 도착 판정(1.5m/0.35rad)을 바꾸지 않고 별도 goal checker(0.45m/0.25rad)를 사용한다. Nav2 성공 뒤에도 실제 TF 자세·정지·새 카메라 프레임을 확인한다. Ackermann 차량이 제자리 회전한다고 가정하지 않는다.

LLM은 등록된 장소와 허용된 임무 한 개만 제안하고 Mission Manager가 검증한다. 쉘 실행·임의 좌표·속도 명령을 생성하지 않는다. 미등록 장소/애매한 요청/복합 순찰은 설명을 요청한다. VLM은 보이는 구역만 판단하며 안내문이 안 보이거나 가려진 경우 판단 불확실로 보고한다. 불 꺼짐만으로 영업 종료를 확정하지 않는다.

중복 HTTP 재전송은 같은 요청 ID의 임무를 재실행하지 않는다. Nav2 실패와 API 실패를 구분하고 사진은 분석 실패에도 남긴다. 취소 요청과 실제 Nav2 종료 확인을 구분해 표시한다. 한 번에 웹 임무 한 개를 실행한다.

## 자원과 기록

- 로컬에는 LLM/VLM 가중치를 올리지 않는다. API 호출은 요청 해석과 도착 후 분석에만 사용한다.
- 상태는 약 1Hz, 카메라 미리보기는 1.5초 간격·최대 640×480, 관찰 사진은 최대 1600×1200이다.
- 수 GB의 DB 사본, 연속 영상, rosbag은 생성하지 않는다. 지도 PNG는 서버에서 한 번 변환한다.
- 기본 기록은 SSD의 `~/ros2_ws/mission_data/`에 SQLite와 임무별 JPEG 2장으로 저장한다. 기록 자동 삭제는 하지 않으므로 장기 운영 시 보관 정책을 추가한다.
- 브라우저와 API 키는 분리되며 키는 Jetson의 환경 설정에서만 읽는다. 모델 요청은 `store:false`지만 사진·프롬프트는 외부 API로 전송된다.

## 검증 범위와 근거

임무 상태 전이·중복/취소·지도 불일치·촬영 실패·API 오류, 별도 ROS domain의 Action/TF/카메라 연결, 실제 Nav2의 일반/관찰 도착 판정과 기존 전후진·장애물 경로, 데스크톱/모바일 화면을 검증한다. 실제 API 키 호출과 map1 세 목적지 실차 도착/사진 구도는 별도 현장 확인 대상이다.

구현은 [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling), [이미지 입력](https://developers.openai.com/api/docs/guides/images-vision), 설치된 Humble Nav2의 `NavigateToPose`/`ComputePathToPose`/`FollowPath` 인터페이스를 사용한다. 장소 이름을 인식해 좌표를 자동 발견하는 시맨틱 탐색이나 자동 관찰점 재선정은 포함하지 않는다.

외부 연결 방식과 제약은 [Cloudflare Quick Tunnels 공식 문서](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)를 따른다. 계정/도메인 없이 테스트할 수 있지만 가용성 보장은 없고 임시 호스트명이 바뀐다. 현재 앱은 SSE 대신 HTTP polling을 사용한다. cloudflared 2026.10.5 ARM64 공식 바이너리를 SHA-256 확인 후 `~/.local/share/campus-tools/`에 설치하며 Git에는 설치 스크립트만 포함한다.

경로 계산 직후 준비 상태가 잠깐 해제되면 출발 전 최대 120초 동안 같은 목적지를 유지하며
복구를 기다린다. Nav2로 아직 전송하지 않았다고 확인된 경우에만 재전송하며, 통신 응답이
불명확한 Goal을 중복 실행하지 않는다. 대기 중 취소할 수 있고, FCU 오류·시동 해제·지도 불일치는
자동 주행 재개로 우회하지 않는다.
