# ADR-006: 다중 센서 주행과 웹 임무 계층

## 배경

카메라 지도 주행 위에 라이다 회피, GPS 없는 Pixhawk 제어, 웹 목적지·관찰 임무를 추가했다.
ADR-005의 카메라 전용 구성을 확장하되 주행 제어와 AI 임무의 책임을 분리한다.

## 결정

- `rover_navigation`이 센서·매핑·Nav2·ExternalNav 실행을 담당한다. 기존 `gps_navigator`를 대체한다.
- 카메라 모드는 VO, 융합 모드는 유효한 카메라 자세·라이다 속도·Pixhawk 자이로로 로컬 추정을 구성한다.
  융합 입력 노드만 `odom → base_link`, RTAB-Map만 `map → odom`을 발행한다.
- 지도별 센서 구성을 저장한다. 기존 카메라 지도에서도 라이다 로컬 추정·회피를 사용할 수 있지만
  지도에 없던 라이다 관측을 과거 DB와 정합했다고 해석하지 않는다.
- 라이다 costmap, Ackermann 전후진 추종, 장애물 대기·재계획을 사용한다. 후방 실시간 센싱은 없다.
- 웹의 Mission Manager가 장소 YAML과 ROS Action을 실행한다. LLM/VLM은 외부 API이며
  모터 명령·FCU 파라미터를 직접 제어하지 않는다.
- 일시정지는 목표를 유지하며 출력을 차단하고, 취소는 목표를 종료한다. 두 경우 위치추정은 유지한다.
- 부팅 시 웹과 외부 연결만 실행한다. 센서·지도 준비와 시동은 사용자 요청에 따라 진행한다.
- 공개 Git은 `src/`만 관리한다. 지도·키·임무 사진·로그는 분리하며 사용자 홈은 SSD에 둔다.
- 메모리 최적화는 기본 `full`의 지연 특징점 로딩과 DB 캐시를 유지한다. 지역 작업 메모리는
  좌표 일관성 검증이 끝나지 않은 선택 기능으로 남긴다.

## 검증 경계

카메라 주행·라이다 회피의 현장 이력과 최신 구현의 소프트웨어 검증을 구분한다.
최신 융합의 실외 재검증, 조향 하드웨어 확인, 웹에서 관찰 목적지까지의 도착·촬영,
10~20GB 지도 운행은 후속 검증 항목이다. 한 센서가 실패해도 항상 주행을 완료한다는 보장은 없다.
구체적인 설정은 [구조](../architecture.md), [융합](../sensor_fusion.md),
[웹 운영](../campus_missions.md)에 둔다.
