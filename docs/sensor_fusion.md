# 카메라·라이다 융합 주행

`mapping.launch.py sensors:=rgbd_lidar`로 만든 지도는 `localization.yaml`에 센서 구성을
저장한다. 기존 navigation 명령의 `local_odometry:=auto`가 이를 읽어 융합·회피를 켠다.
기존 카메라 지도에서 시험하려면 `local_odometry:=fused`를 지정한다. 이 경우 지도 정합은
기존 영상 DB를 사용하고, 로컬 오도메트리·장애물 감지는 라이다도 사용한다.
라이다 드라이버는 별도 `lidar.launch.py` 또는 통합 런치의 `start_lidar:=true`로 실행한다.

## 추정과 IMU

```mermaid
flowchart LR
  RGBD[RGB-D] --> VO[카메라 VO]
  CAMIMU[카메라 IMU / Madgwick] --> VO
  SCAN[전방 200도 scan] --> ICP[독립 ICP 오도메트리]
  VO --> ALIGN[시간·추적 유효성 / 복구 시 좌표 연결]
  ICP --> ALIGN
  ALIGN --> EKF[2D EKF]
  FCU[Pixhawk raw gyro z] --> EKF
  EKF --> VALID[실제 추적 소스 존재 확인]
  VALID --> ODOM[/odom 및 odom → base_link]
  ODOM --> NAV[Nav2 / ExternalNav]
```

- 카메라 IMU는 VO의 회전 보조로 사용한다. 같은 정보를 EKF에 별도 독립 관측처럼 중복 입력하지 않는다.
- Pixhawk는 `/mavros/imu/data_raw`의 z축 각속도만 EKF에 넣는다. ExternalNav를 융합한
  FCU 위치·속도·yaw를 다시 EKF로 되먹임하지 않는다. RAW_IMU 메시지는 세션 동안 30Hz를 요청한다.
- 카메라는 로컬 x/y/yaw, 라이다는 차체 좌표계의 선속도 x/y 및 회전속도 z를 융합한다.
  서로 독립적으로 누적한 절대 위치를 동시에 강하게 융합하면 누적 오차 차이가 가짜 움직임으로
  나타날 수 있기 때문이다. 동일 소스의 위치와 미분 속도를 중복 융합하지 않는다.
  카메라가 끊겨도 유효한 라이다 속도와 자이로로 추정을 이어가지만, 전역 위치 보정을 대신하지는 않는다.
  평면 주행이므로 가속도를 적분해 위치를 유지하는 방식도 사용하지 않는다.
- 라이다가 차축 기준 옆 방향 속도를 0.20m/s 넘게 보고하거나, 시간 차 0.8초 미만인 유효 카메라 속도와
  0.50m/s 넘게 불일치하면 그 라이다 측정을 제외한다. 명령 속도를 잘라내는 기능이 아니며,
  카메라가 없을 때도 정상 전후진 라이다 추적은 유지한다.
  한 번 제외된 속도 측정은 직전 정상 측정까지 무효화하지 않는다. 마지막 정상 측정의 원래
  타임스탬프를 유지하며, 잘못된 측정만 계속 들어오면 기존 1.5초 제한으로 추적 유효성이 만료된다.
- 카메라 VO·ICP·EKF 자체의 TF 발행은 끈다. `fusion_inputs`만 유효한 `odom → base_link`를 발행한다.
  `map → odom`은 RTAB-Map이 맡는다.
- 지연된 측정은 최대 1.5초 EKF 이력으로 처리한다. EKF 20Hz 출력은 센서 20Hz 관측이라는 뜻이 아니다.
- 카메라 또는 라이다 하나가 실패해도 다른 소스가 유효하면 추적을 유지한다. 둘 다 실패하거나
  실제 측정이 1.5초 이상 없으면 예측만으로 정상 상태를 만들지 않는다.
- 센서 재시작 시 첫 샘플로 현재 로컬 좌표에 연결하고 다음 실제 변화부터 융합한다.
  절대 위치를 새로 알아낸 것이 아니며, 장시간 단독 추적의 누적 오차를 제거하는 기능은 아니다.

카메라 VO는 최신 프레임 우선·영상 계산 2배 축소·1,000개 특징점·2,000개 로컬 특징점 한도를 사용한다.
새 촬영 설정은 화면을 2×3으로 나누어 특징점을 배분하고, 깊이 구멍 때문에 RGB 특징점까지
제외하지 않도록 한다. 최소 대응점 20과 정합 검증은 유지한다. 융합 모드에서는 연속 10프레임
추적 실패 후 VO가 재초기화한다. 기존 지도별 촬영 설정은 자동 덮어쓰지 않는다.

카메라가 멈추면 라이다로 로컬 경로 추종은 이어갈 수 있지만, 현재 구현의 RTAB 전역 보정은
처리된 RGB-D에도 의존한다. **라이다만으로 전역 재정합하는 별도 시스템은 아니다.**

## 장애물 처리

전방 scan을 global/local costmap에 표시하고 유효한 관측으로 지운다. 전방의 정상적인 무반사
`+Inf`는 최대 raytrace 범위 안의 오래된 장애물 제거에 사용한다. 후방·자체 차체 반사·
잘못된 수치는 NaN으로 제외한다. 강한 햇빛에 의한 무반사까지 구분하는 센서 기능은 아니다.
Hybrid-A*는 회전반경 2m로 재계획하고 RPP는
곡률·장애물 비용에 따라 감속한다. 원래 직선 0.35m/s와 명령 상한 0.4m/s는 유지한다.

라이다 모드의 행동트리는 최대 2Hz 재계획, 유효한 기존 경로 유지·효율 비교, 경로 추종을 사용한다.
실패 시 3초 대기 후 재시도하며 60회 복구도 실패하면 목표가 종료될 수 있다.
계획된 전후진 구간은 Ackermann 추종기가 실행한다. 별도의 무조건 후진·제자리 회전·장애물 강제 삭제
복구는 없다. 사람 등으로 막히면 먼저 감속·대기하고 지속되는 장애물에 대해 재계획한다.
통로가 없으면 기다리며, 불가능한 경로를 강제로 만들지 않는다.

Collision Monitor가 곧 충돌할 속도를 줄이거나 0으로 만든다. 스캔 자체가 2초 넘게 끊기면
어댑터도 0 명령으로 대기한다. 이 대기는 HOLD 요청이나 정지 latch를 만들지 않으며,
센서·통로가 복구되고 유효한 명령이 있으면 같은 목적지로 진행한다. 실제 추정 전체 실패,
제어 명령 단절, FCU 추정 실패 등 기존 치명적 오류 처리는 유지한다.

Humble의 Collision Monitor는 오래된 scan을 무시하므로, 스캔 누락 정지는 어댑터에서 보완했다.
융합 주행에서는 신선하고 유한한 자세의 공분산이 기존 기준의 2배 이내로 잠깐 높아진 경우에만
최대 1초 동안 추정을 유지한다. 큰 공분산·비정상 좌표·추적 상실을 허용하는 설정은 아니다.
융합 추적 상태가 잠깐 상실되면 출력은 즉시 0으로 만들되 최대 1초 동안 목표를 유지한다.
그 안에 정상 측정이 복구되면 안정 판정 후 같은 목표로 재개하고, 상실이 계속되면 정지 latch와
목표 취소를 수행한다. 카메라 전용 모드의 명시적인 추적 상실 정책은 바꾸지 않는다.
실내 정지 및 합성 센서 검증을 실제 야외 회피 성공으로 해석해서는 안 된다.

## 검증과 한계

정지 상태의 RGB-D·scan 동시 매핑과 DB 저장을 확인했다. 격리 ROS에서 실제 EKF를 사용해
단일 센서 실패·카메라 좌표 리셋·전체 추적 상실·지속 이상 시 출력 중단을 검증한다.
서로 독립적인 누적 위치의 차이가 가짜 이동으로 융합되지 않도록 라이다는 속도만 입력한다.
실제 Humble Collision Monitor와 Nav2를 합성 지도·센서에 연결하여 장애물 감속·제거 후 재개,
계획된 전후진·스캔 누락 대기·짧은 추적 상실 복구를 검증한다.

기존 융합·라이다 회피의 현장 시험 이력은 있지만, 최신 라이다 속도 입력·복구 정책으로
실외 목적지까지 도착하는 검증은 아직 필요하다. 정지 시험과 합성 회귀 결과는 그 대체물이 아니다.

야외 햇빛, 낮은 구조물, 넓고 특징 없는 광장에서는 RGB-D와 200도 2D scan이 동시에 약해질 수 있다.
레이저 높이 25cm의 단면에 안 걸리는 장애물, 낙차, 후방 장애물까지 감지하지 않는다.
실제 장착 방향은 RViz에서 차량 정면 물체와 scan 정면이 일치하는지 확인해야 한다.
센서가 늘었다는 이유만으로 무조건 위치 정확도가 높아지거나 무정지 주행을 보장하지 않는다.

현재 추적 소스 확인:

```bash
ros2 topic echo /localization/fusion_status std_msgs/msg/String --qos-durability transient_local
```

`valid_sources`에 `visual` 또는 `lidar`가 있으면 해당 추적이 유효하다.
지도 정합 성공 여부는 별도 `/navigation/status`에서 확인한다.
